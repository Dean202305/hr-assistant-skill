# 员工全生命周期工作流

适用于把招聘录用、入职、试用、在职变动、续签和离职转成可跟进的任务台账或操作清单。它是流程辅助，不代替 HRIS、审批系统或有权人员的决定。

## 先确定适用边界

取得用人单位、员工工作地、员工稳定 ID、员工类别、合同类型、适用的公司制度、任务负责人和数据来源。信息缺失时先建立待配置台账；不得从姓名、身份证号或简历猜测合同状态、手续是否完成。

同一员工可有多个历史事件。用 `员工ID + 事件ID + 生效日期` 关联，保留原始记录与变更日志；不要用姓名或表格行号覆盖历史。

## 生命周期事件

| 阶段 | 触发与典型核对 | 交付物 |
| --- | --- | --- |
| 编制与录用 | 已批准岗位、预算、录用条件、offer 与入职日期是否一致 | 录用核对表、待办清单 |
| 入职 | 合同签订、资料收取、岗位/部门、薪酬口径、社保公积金城市、账号与培训 | 入职办理台账、缺件提醒 |
| 试用与转正 | 试用期限、考核标准、过程反馈、转正决定及告知 | 试用期里程碑和证据清单 |
| 在职变动 | 调岗、调薪、组织变更、休假、长期缺勤或劳动条件变更 | 变更前后对照、审批与告知记录 |
| 续签 | 合同到期、续签意向、适用合同类型和期限、授权审批 | 到期提醒、续签核对表 |
| 离职 | 离职原因与依据、审批、结算、资产交接、证明、档案与社保关系手续 | 离职清单、未结事项、档案处置登记 |

节点具体期限、材料和责任人以适用法律、所在地规则及经批准的公司制度为准；未核实的法律期限不得写成默认值。发生争议、处分、单方调岗、解除或裁员时，转读 [用工风险核查](employment-risk-check.md)。

## 最小台账结构

- `员工主数据`：员工ID、部门/岗位、用工类型、入职/离职日期、合同状态、数据来源、最后核验日期；敏感字段按需单独授权。
- `事件台账`：事件ID、员工ID、事件类型、发起日期、生效日期、发起人、审批人、状态、依据、关联文件、版本。
- `任务清单`：任务ID、事件ID、责任人、截止日期、完成日期、证据位置、异常原因、复核人。状态至少区分“待办、进行中、待人工确认、已完成、已取消”。
- `到期提醒`：规则名称、事件基准日期、计算口径、提醒日期、接收人、发送状态；没有确认基准日期或规则时不发送貌似确定的到期通知。

生成 Excel 时读取 [表格规格](workbook-specs.md)；用户明确要求周期提醒时再读取 [自动化规则](automations.md)。完成后核对员工数、事件数、未结任务数与来源清单；抽查入职、续签、调岗、离职各一例，避免跨员工串档。

## 离职档案与销毁

如本地存在 `company-policy.local.md`，在计算公司档案留存和销毁提醒前读取其中的批准规则；该本地文件不得被复制进公开仓库或对外报告。对每类记录另存处理目的、法律/制度依据、保管责任人、起算事件、期限、争议或调查封存状态、到期处置方式。

公司提出“离职后第 5 年销毁”时，将其作为公司规则参数，而非所有记录的普遍法定期限。首次执行前确认“第 5 年”的准确起算和截止日期；到期前检查是否仍有必要留存、是否存在更长的强制期限或争议保全。没有授权审批不得自动销毁，只生成待复核清单和可追溯的处置记录。

参考：[《劳动合同法》第五十条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_0abfdd261c03417b949df19d869add8d.html)、[《个人信息保护法》第十九条](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)。
