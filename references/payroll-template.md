# 薪酬计算表规则

## 来源模板基线

用户提供的《工资模版_整理至7月.xlsx》包含 1—12 月工资明细、年度工资汇总和计税整理。薪酬表应继承其业务链路，但不得复制其中的真实人员和工资数据。

月度明细基线字段：序号、姓名、员工状态、一级部门、二级部门、三级部门、职位、税前薪资、基本工资、岗位津贴、绩效奖励、其他补贴、月度完成数、绩效 bonus、上月差额、社保基数、公积金基数、社保公司缴纳、社保个人缴纳、公积金公司缴纳、公积金个人缴纳、应出勤天数、实际出勤天数、事假天数、病假天数、迟到天数、事假扣除、病假扣除、迟到扣除、绩效考核结果、应发底薪、应发岗位工资、绩效实发、应发补贴、应发工资（税前）、累计计税工资、累计专项附加扣除、累计减除费用、累计应纳税所得额、累计应预扣税额、当月应缴个税、实际应发工资。

可选核对字段：本月实际到账、差额。仅在用户有银行到账数据时启用。

## 公式关系

- 税前薪资 = 基本工资 + 岗位津贴 + 绩效奖励 + 其他补贴。
- 应出勤天数由目标月份、工作日制度和法定节假日参数计算。不要照搬模板中某个月份或不透明公式。
- 实际出勤天数 = 应出勤天数 − 事假天数 − 病假天数 − 其他需要扣减的缺勤天数。迟到是否折算成天数由公司规则决定，不默认混入。
- 事假扣除、病假扣除、迟到扣除均使用 `参数设置`中的明确规则。附件曾使用“日薪×事假天数”“病假按 50%”“迟到每次 50 元”，这些只作为模板历史口径，未经用户确认不得作为新公司的默认制度。
- 应发底薪 = 基本工资 − 适用的考勤扣款。
- 应发岗位工资 = 岗位津贴或其考核后金额，依用户制度。
- 绩效实发 = 绩效奖励 × 绩效考核系数，或按用户给定奖金规则计算。
- 应发工资（税前） = 各应发项目 + 绩效 bonus + 上月差额。
- 实际应发工资 = 应发工资（税前） − 个人社保 − 个人公积金 − 当月应缴个税 − 其他明确的税后扣款 + 税后补发。

## 社保、公积金与个税

附件历史公式中存在固定比例和累计个税计算，但城市政策、上下限和年度税务口径会变化。新表必须：

1. 在开始社保公积金核算前询问用户缴纳城市和适用年月，允许一次配置多个城市；随后查询各城市五险与公积金的现行基数上下限和费率。
2. 在 `参数设置`按城市、险种和生效期间维护企业/个人费率、基数上下限、公积金比例、专项附加扣除、累计减除费用和税率表，并记录权威来源链接与核验日期。
3. 明细按“缴纳城市 + 工资所属月 + 险种”精确查找政策，自动切换对应基数和费率。同一员工更改城市或月份后，养老、医疗、失业、工伤、生育和公积金都要重新匹配。
4. 各险种分别执行上下限约束，不假定五险共用同一基数范围；公积金基数和比例独立匹配。无法唯一匹配时停止计算并提示待配置。
5. 仅在参数完整时计算；参数缺失时显示具体的待配置提示。
6. 对员工状态（正式、实习、劳务等）的适用规则使用显式映射表，不把“实习/劳务一定为零社保”写死。
7. 累计预扣法按同一纳税主体和累计周期滚动。换公司、劳务报酬、一次性奖金或用户指定的独立计税情况必须分开处理并注明。

## 年度汇总

按稳定员工编号汇总 1—12 月，至少包含：姓名、员工状态、一级部门、二级部门、三级部门、职位、公司社保年度支出、公司公积金年度支出、年度应发总额、年度实发总额、年度个税。汇总必须覆盖新增员工、离职员工和同名员工，不得按固定行号跨月相加。

## 核验

- 抽测正式、实习/劳务、当月入离职、零绩效、缺勤、补发、跨累计周期等情形。
- 月度勾稽：应发工资、个人扣款、个税和实发工资关系一致。
- 年度勾稽：年度汇总等于 12 个月对应明细之和；空月份不误计为零。
- 多城市勾稽：切换缴纳城市或跨越政策生效月后，五险及公积金基数、费率与企业/个人支出均取自唯一对应的城市期间参数。
