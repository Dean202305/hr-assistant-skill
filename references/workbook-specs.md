# HR 表格规格

## 共通要求

- 新工作簿默认包含必要的业务表、`参数设置`，以及确有独立汇总需求时的汇总表。
- 每张明细表启用筛选、冻结标题行、表格样式和合理列宽。敏感字段默认文本格式，避免身份证号和手机号科学计数或丢失前导零。
- 下拉选项集中维护在 `参数设置`，可隐藏辅助区域但不要隐藏关键业务参数。
- 使用稳定的员工编号或候选人编号作为跨表关联键；姓名仅作展示，避免同名错配。
- 不填充虚构员工或候选人。需要演示时使用明显的虚构数据并在交付前按用户要求保留或移除。

## 花名册

字段顺序：序号、姓名、性别（由身份证号解析）、年龄（由身份证号和基准日期计算）、出生日期（由身份证号解析）、身份证号、身份证校验结果、婚育情况、联系电话、户籍省市（按身份证前六位行政区划码解析）、户籍地址、现居住地址、毕业院校、所学专业、学历、紧急联系人姓名、与紧急联系人关系、紧急联系人电话、入职资料。

下拉选项：

- 婚育情况：未婚、已婚未育、已婚已育、离异未育、离异已育
- 学历：初中及以下、高中、中专、大专、本科、硕士、博士
- 入职资料：已收齐、未收齐

规则：身份证为空时，自动字段保持空白；身份证无效时，解析字段不得显示貌似可信的结果。年龄使用“基准日期”参数，按周岁计算，不直接用当前年份减出生年份。联系电话和紧急联系人电话只做格式提示，不虚构真实性验证。

## 社保公积金核算表

每月一张明细表，字段为：序号、姓名、一级部门、二级部门、三级部门、职位、是否实习、缴纳城市、社保缴纳基数、养老保险、医疗保险、失业保险、工伤保险、生育保险、公积金缴纳基数、公积金缴纳百分比、企业支出、员工支出。

- 开始制作前先询问用户员工的社保公积金缴纳城市和适用年月。用户可以一次提供一个或多个城市；若只有部分员工异地缴纳，也要将全部实际缴纳城市纳入配置。
- 对每个城市查询适用期间内养老、医疗、失业、工伤、生育五个险种及住房公积金的缴费基数下限和上限。不同险种若采用不同口径必须分别保存，不得用一个“社保基数上下限”覆盖所有险种。
- 查询优先使用当地人力资源和社会保障局、医疗保障局、税务局、住房公积金管理中心及政府门户发布的现行文件。记录政策名称、官方链接、发布日期、生效日期和适用期间；新闻转载、计算器和商业网站只能作为线索，不能作为唯一依据。
- 官方政策尚未发布、来源冲突或缺少某险种上下限时，将该城市/险种标为“待确认”，向用户说明具体缺口，不能沿用其他城市或旧年度参数冒充当前值。
- `参数设置`建立城市政策表，至少包含：城市、政策生效起始月、政策失效月、险种、基数下限、基数上限、企业费率、个人费率、附加固定金额、来源及核验日期。公积金另保留单位比例、个人比例及允许比例范围。
- 明细行以“缴纳城市 + 工资所属月 + 险种”为查找键，自动切换对应城市和期间的上下限及费率。不得只按城市查找最新值，以免历史月份被新政策覆盖。
- 各险种实际缴费基数按其当地上下限封顶保底。若用户输入申报基数，则使用 `MIN(MAX(申报基数, 下限), 上限)`；若按工资确定基数，先确认采用当月工资、上年度月平均工资或当地规定的其他口径，再应用上下限。
- 找不到唯一匹配政策、同一期间重复配置或缴纳城市为空时，公式显示明确错误/待配置状态，并停止该行费用计算，不能静默使用默认城市或零费率。
- `是否实习`下拉：是、否。
- 保险项目不得只放一个不明方向的金额。若用户未明确是企业还是个人部分，在参数表保留企业费率和个人费率两组，明细列按用户要求显示项目总额或拆分列，并在表头写清口径。
- `企业支出`至少等于企业承担的五险合计加企业公积金；`员工支出`至少等于个人承担的养老、医疗、失业和个人公积金。工伤、生育默认不推定个人承担比例。
- 标题下一行展示：当月企业社保支出费用、当月企业公积金支出费用。金额由明细汇总公式生成。
- 最后一张 `年度汇总`列示 1—12 月的企业社保支出、企业公积金支出，以及年度企业社保总支出、年度企业公积金总支出。月份缺失时显示空白或待录入，不伪装成零支出。

多城市核验至少覆盖：同月两个城市基数不同、同城跨政策生效月、工资低于下限、工资高于上限、某险种单独上下限、城市未配置和政策期间重叠。抽测时确认修改“缴纳城市”后五险及公积金基数、费率、企业支出和员工支出同步切换。

## 招聘台账

字段顺序：序号、日期、应聘岗位、候选人姓名、候选人年龄、毕业院校、专业、学历、工作年限、投递岗位亮点、与岗位匹配程度、初试面试官、初试面试结果、复试面试官、复试结果、终试面试官、终试结果、offer情况、入职情况。

下拉选项：

- 学历：初中及以下、高中、中专、大专、本科、硕士、博士
- 初试/复试/终试结果：通过、待定、未通过
- offer情况：待发、已发未回、已发已回
- 入职情况：未入职、已入职

`工作年限`单位为年，允许小数；`与岗位匹配程度`优先采用用户提供的等级或百分比口径，没有口径时保留为空并请求定义，不擅自构造评价模型。

## 招聘漏斗汇总

在招聘工作簿内增加 `招聘汇总`。提供统计起止日期和周期选择：周、月、季、半年、年。基于真实日期字段按边界筛选，不能按文本月份猜测。

漏斗节点：简历数量、通过筛选数、初试邀约数、初试通过数、复试邀约数、复试通过数、终试邀约数、终试通过数、offer数、入职数。

用户尚未定义“通过筛选”和各轮“邀约”的原始字段。为避免从面试结果反推邀约，建表时增加必要的流程状态/邀约日期辅助字段，或将这些节点标记为待配置，先让用户确认口径。

每个节点都显示数量和转化率。转化率按相邻阶段计算，例如 `初试通过率 = 初试通过数 / 初试邀约数`。分母为零时显示 `n.a.` 或空白，不显示 0%。图表按漏斗顺序排列，图表数据与汇总表公式直接关联。

## 360 度环评

生成问卷、答卷录入表或统计工作簿时，先读取 [360 度环评规则与题库](360-feedback.md)。支持用户提供的 20 道单选题、2 个姓名字段、2 道开放题的通用版，以及问卷星链接所示的“下级对上级”版；后者只作为结构与维度参考，使用前重新核验页面是否可访问及内容是否变化。

默认工作簿分开保存 `填写说明`、`题目与选项`、`原始答卷`、`统计汇总`、`参数设置`。每份答卷一行，使用答卷 ID 和被评估者 ID 关联，不以姓名作为唯一键。原始题目回答保持原样；分值映射、关系组别权重和维度归属另放参数表，变更参数不得覆盖原答卷。未答与“不确定”分开统计，不能当作最低分或零分。

生成前确认使用哪一版、评估对象与评价人关系、是否匿名、统计或评分需求、分组权重和输出范围。未提供权重或评分规则时先交付可填写问卷与选项分布汇总，不擅自宣称综合得分或考核等级。小样本与可识别的自由文本反馈需限制访问，报告中避免暴露匿名评价人的身份。质量检查包括：20 题选项验证、姓名/ID 与关系字段、三条优势和三条改进建议的录入空间、无效选项、漏答数、答卷数与统计数勾稽，以及不同量表不混算。

## 岗位胜任力模型

创建岗位能力词典、分级矩阵或评估工作簿时，读取 [胜任力模型构建规则与候选指标](competency-model.md)。至少分开保存 `建模说明`、`胜任力词典`、`岗位等级矩阵`、`行为证据与评估`、`参数与版本`。如只有概念设计而无员工评估数据，交付词典和岗位矩阵即可，不生成虚构评分。

词典每行一项胜任力，保留唯一 ID、岗位/职位族、名称与定义、关联任务及绩效标准、用户所选分类视角、可观察行为、等级锚点、证据与评估方法、来源、适用版本。岗位矩阵只引用词典 ID，不靠名称模糊匹配。权重、最低等级、总分算法和通过阈值由用户确认；缺失证据显示“待验证”，不写成 0 分。核验权重合计、等级边界、公式重算、交叉引用、版本生效日期，以及员工评分与原始证据是否一一对应。

## 人才盘点

生成九宫格、四象限、人才地图、继任或培养计划时，先读取 [人才盘点规则与模板](talent-review.md)。九宫格使用`绩效 × 潜力`三档，用户参考图片的四象限使用`绩效表现 × 工作能力`两档；工作能力不是潜力的同义字段，两张图应有独立参数、来源和结果。未确认档位阈值、潜力目标岗位/期限或四象限能力定义时，可以交付空白模板和待配置参数，不能自动给员工贴标签。

默认按交付需要设置`盘点说明与参数`、`原始评估`、`校准记录`、`九宫格`、`四象限`、`行动计划`和`汇总`，不强制增加没有数据的工作表。以员工稳定 ID、盘点周期和模型版本作为关联键；保存绩效与潜力/能力的原始依据、校准前后档位和变更理由。每名纳入统计的员工在所选矩阵中只能落入一个格子，证据不足者列为“待评估”，不能被计入低档。汇总人数应与有效明细勾稽；小样本展示、具名名单和继任信息应限制授权访问。
