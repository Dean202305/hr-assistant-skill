# AIHR：一句话调用 HR 与企业架构知识库

AIHR 是一个统一入口的通用 Agent Skill。用户用一句话提出“AIHR + 需求”，它根据需求关键词加载对应知识库，完成员工全生命周期跟进、用工风险核查、编制与人力成本分析，以及 HR 表格、简历分析、内部公告、自动化任务、人才管理或企业架构规划设计。

只有一个 [SKILL.md](SKILL.md) 入口和一组按需读取的 `references/` 知识库；企业架构不再需要另装或另行触发。关键词只是路由线索，Skill 仍会理解完整需求、附件和上下文；跨模块任务可同时读取多个知识库。

核心采用通用的 `SKILL.md + references/` 目录结构，不绑定特定模型，可安装到 Codex、Claude Code、WorkBuddy、DeepSeek Harness、OpenClaw，以及其他能够读取目录式 Agent Skills 的软件或智能体框架。

它不仅生成内容，还强调公式正确性、政策时效性、证据可追溯、敏感数据保护和人工复核边界。新加入的人才类模板保留评分口径、校准记录和版本信息，避免把一次问卷、一张九宫格或未经验证的能力标签直接变成人事决定。

不同平台提供的工具并不完全相同。表格生成、Word 文件、联网检索、文件复制和定时任务等功能，需要宿主软件具备对应的文件系统、办公文档、浏览器/搜索或调度工具。缺少某项工具时，核心规则仍可用于分析和起草，但无法保证产生相同的文件或自动化结果。

“AIHR + 需求”的自然语言触发取决于宿主是否支持技能自动发现；若未自动加载，使用该平台的显式技能命令（如 Codex 的 `$aihr`），仍然只需一句话。

## 核心能力

### 1. HR 表格生成与维护

可以根据用户需求创建或维护：

- 员工花名册
- 薪酬计算表
- 社保公积金核算表
- 招聘台账和招聘漏斗
- 360 度环评问卷、答卷表与统计汇总
- 岗位胜任力词典、等级矩阵与行为评估表
- 人才盘点九宫格、四象限、人才地图与行动计划

花名册支持身份证格式与校验位检查，并在身份证有效时计算性别、出生日期和周岁年龄。婚育情况、学历、入职资料等字段使用规范下拉选项，身份证号和手机号按文本保存，避免科学计数和前导零丢失。

### 2. 薪酬计算与年度汇总

薪酬模块参考真实工资模板的业务链路，覆盖：

- 基本工资、岗位津贴、绩效奖励和其他补贴
- 考勤、事假、病假及迟到扣款
- 社保、公积金企业与个人部分
- 应发工资、累计计税、当月个税和实发工资
- 1—12 月工资明细和年度汇总
- 一级、二级、三级部门管理

费率、扣款标准、工作日、计税周期等内容集中放在参数区，不将临时口径散落在公式中。年度汇总使用稳定员工标识关联，降低同名人员和跨月行号变化导致的错算风险。

### 3. 多城市社保公积金核算

制作核算表前，助手会先确认缴纳城市和适用年月，并支持一次配置多个城市。

针对每个城市，它要求查询养老、医疗、失业、工伤、生育和住房公积金的基数上下限、单位费率和个人费率。优先采用人社局、医保局、税务局、公积金中心和政府门户等官方来源，并记录政策名称、生效期间、链接与核验日期。

明细表以“缴纳城市 + 工资所属月 + 险种”为匹配键。切换员工的缴纳城市或月份后，对应的基数上下限、费率、企业支出和个人支出会同步切换。政策缺失、期间重叠或无法唯一匹配时，结果会标记为待确认，而不是静默套用默认城市或旧年度参数。

### 4. 批量简历分析与筛选

执行筛选前会确认：

- 简历目录和子目录范围
- 需要筛选的文件范围
- 岗位职责、硬性条件、关键词或岗位画像文件
- 宽松、中等或严谨档位
- 项目经验能否替代工作或实习经验
- 输出位置

三个档位分别对应：

| 档位 | 最低综合评分 |
| --- | ---: |
| 宽松 | 7.0 |
| 中等 | 8.0 |
| 严谨 | 9.0 |

每位候选人按照学历及专业、岗位经历、核心技能、项目经验、成果及业务影响、简历可信度和优秀候选人共性进行多维分析。综合评分为 0—10 分并保留一位小数。

每次批量筛选固定生成：

```text
简历筛选结果_YYYYMMDD/
├── 全部候选人岗位评分.xlsx
├── 通过筛选的候选人.xlsx
└── 通过筛选的候选人简历/
    ├── 岗位A/
    └── 岗位B/
```

所有扫描到的简历都会进入完整台账。无法读取、内容为空、文件加密、格式损坏或关键信息无法确认的文件不会被跳过，而会记录失败原因和人工处理要求。

达到档位分数线的候选人原始简历会按岗位复制到结果目录。复制过程不移动、不删除、不修改源文件，也不改变原始文件名。

### 5. 招聘台账与漏斗

招聘模块记录候选人的岗位、教育背景、工作年限、匹配亮点和各轮面试结果，并支持按周、月、季度、半年和年度汇总。

漏斗可以统计：

- 简历数量
- 通过筛选数
- 初试邀约数与通过数
- 复试邀约数与通过数
- 终试邀约数与通过数
- Offer 数
- 入职数

每个阶段显示数量和相邻环节转化率，避免使用不一致的分母。缺少邀约字段或流程定义时，会先要求补充口径，不从面试结果反推邀约数量。

### 6. 公司内部公告与制度草拟

支持草拟包括但不限于：

- 放假通知
- 员工调动通知
- 加班或调班通知
- 违规违纪公告
- 考勤、休假、加班和奖惩制度
- 员工手册及其他劳动用工文件

每次具体草拟任务都会根据文件主题、适用日期、用人单位所在地和员工工作地检索相关现行规则。优先使用国家机关、地方政府、人社部门、司法机关等权威来源。

工作流先生成中性、清楚、可执行的标准版初稿，再询问用户是否需要调整事实或条款，以及是否改写为简洁、和蔼、搞怪、严肃等风格。风格只改变表达，不会弱化关键条件、员工权益或风险提示。

### 7. HR 定时任务

可以把重复性的 HR 工作转换为定时任务，例如周期性生成报表、检查资料缺失情况或监控招聘流程变化。

自动化会明确数据来源、统计期间、输出位置、异常处理、通知条件和停止条件。默认仅在产生有意义的变化、完成、失败或需要人工操作时通知，避免无变化时反复打扰。

### 8. 360 度环评

新增两种互不混算的问卷模板：用户提供的通用版包含 20 道单选题、被点评人与点评人姓名，以及各三条“优势”“待改进”意见；[下级对上级版参考问卷](https://www.wjx.cn/m/37408323.aspx)则侧重职业素养、统筹规划、沟通推动、领导力、员工关怀等管理行为，采用独立的 1—5 分量表。

Skill 可以据此生成可填写问卷、原始答卷 Excel、选项分布和统计汇总。创建前会确认评价关系、是否匿名、评分映射、各关系组别权重和结果权限。未确认评分规则时，只统计答卷与选项分布，不擅自生成“综合分”或考核结论；“不确定”与漏答分别计数。通用版原引导语使用“自己”，与具名点评他人的字段存在口径冲突，实际发放前会提示确认。具名意见和小样本结果需要限制访问，避免暴露评价人身份。完整题库与表格口径见 [360 度环评规则](references/360-feedback.md)。

### 9. 岗位胜任力模型

可从企业目标、岗位任务和绩效标准出发，构建能力词典、岗位等级矩阵、行为评估表及发展建议。支持用洋葱模型和冰山模型整理知识、技能、角色、自我认知、特质与动机等要素，但不会凭简历或一次面试推断“深层特质”，也不会把模型隐喻当作已经验证的评分公式。

内置六类可调整的行为素材：创造性与灵活性、实用性与实践性、团队合作、诚信可靠与责任心、持续学习与自我完善、客户价值服务。建模流程覆盖绩效标准定义、行为事件访谈/问卷/专家讨论、指标提炼、可观察的等级锚点、试用验证和版本发布。指标必须能追溯到岗位任务；权重、门槛和正式考核用途由用户确认。详见[胜任力模型构建模板](references/competency-model.md)。

### 10. 人才盘点

支持两种独立模板：九宫格用“绩效 × 面向目标岗位的潜力”三档交叉；用户提供的参考图片是“绩效表现 × 当前工作能力”的四象限，两者不互相换算。模板覆盖准备、评估与校准、结果应用三个阶段，记录原始证据、校准前后变化、行动负责人和复盘时间。

可按确认后的口径生成人才地图、关键岗位继任清单和个人发展计划。九宫格先使用中性坐标码；“明星人才、核心骨干”等名称作为可配置展示别名。未确认绩效/潜力/能力的定义与阈值，或缺少员工证据时，不自动归格；格子位置也不直接触发晋升、调岗或淘汰。详见[人才盘点规则与模板](references/talent-review.md)。

### 11. 员工全生命周期

把已批准编制和录用、入职、试用转正、在职变动、续签、离职交接转成可追踪的事件与任务。每个节点记录责任人、期限、审批、证据和异常；不从姓名或表格行号推断员工状态。可生成台账、缺件清单和到期提醒，涉及处分或解除时转入用工风险核查。详见[员工全生命周期工作流](references/employee-lifecycle.md)。

### 12. 用工风险核查

围绕合同、工资加班、调岗、纪律处分、解除终止等事项，把事实、证据、适用规则、程序和待确认问题分开记录。输出风险清单与可选路径，不把缺少证据的推测写成结论，也不替代授权 HR 或法务作决定。详见[用工风险核查规则](references/employment-risk-check.md)。

### 13. 编制与人力成本分析

将业务计划、批准编制、实际在岗、招聘需求和成本预算放在同一口径下核对。支持期间人数勾稽、成本测算、预算差异和情景比较；费率、增长率及离职假设均为显式参数，不预填虚构数字。详见[编制与人力成本分析规则](references/workforce-planning.md)。

## 主要优势

### 结构化交付，而不只是聊天结论

需要表格时会实际生成可筛选、可复核的 Excel；批量简历分析必须包含完整评分台账和候选人明细，不能用一段概述替代正式结果。

### 强调完整性与可核对性

简历筛选要求扫描数量与 Excel 记录数量一致，达标候选人与复制文件逐一核对。薪酬和社保表要求月度、年度汇总勾稽，并检查公式、缺失参数和异常结果。

### 多城市、多期间政策管理

社保公积金不使用单一固定费率。城市、险种和政策期间共同决定适用参数，更适合异地用工、多分支机构和跨年度核算场景。

### 降低信息幻觉

无法确认的学历、院校排名、工作时间、项目周期、候选人姓名和岗位匹配信息会明确标记为“无法确认，需要人工复核”，不会通过常识或文件名补全。

### 保护个人信息

身份证号、联系电话、住址、工资、婚育信息和简历内容均按敏感个人信息处理。规则要求最小化使用和披露，不将真实个人数据写入示例、日志或公开资产。

公司档案保存期限可通过本地 `references/company-policy.local.md` 配置，不随公开仓库发布。AIHR 可按经确认的公司规则生成到期提醒，但销毁前仍需核对记录类别、适用保存要求、争议保全和审批；不会自动删除档案。[《个人信息保护法》第十九条](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)要求保存期限与处理目的相匹配，[《劳动合同法》第五十条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_0abfdd261c03417b949df19d869add8d.html)对已解除或终止劳动合同文本另有最低保存要求。

### 关注公平招聘

评分只使用与岗位相关的能力和证据，不得根据性别、年龄、婚育、民族、籍贯、外貌、宗教或残障等无关信息进行评分和淘汰。年龄可以用于合法、必要的业务记录，但不能作为直接淘汰依据。

### 保留人工决策边界

本助手提供分析、证据和风险提示，不替代最终录用、处分、薪酬或劳动关系决策。置信度不足、硬性条件不清楚、项目职责不明确或时间线冲突时，会进入人工复核。

### 用工文件先标准、后风格

公告先保证事实完整、行动明确和表达稳妥，再按用户需要调整风格。遇到明显违法或高风险条款时，会提示风险并提供尽量接近原业务目的的替代写法，而不会把高风险内容包装成可直接发布的正式文件。

## 企业架构规划与设计知识库

面向企业级或业务域级数字化规划，从战略目标和端到端价值流出发，形成可实施的架构方案。它把用户提供的长篇架构材料提炼为可重复执行的工作流，而非原文转载：

- 梳理规划边界、现状证据、业务能力与流程，区分事实、假设和建议。
- 形成业务、数据、应用、技术四类视图，并用映射表追溯“业务目标 → 能力/流程 → 数据 → 应用/服务 → 技术”。
- 对跨系统流程设计应用、数据和门户集成，明确接口契约、数据归属、运行责任与安全要求。
- 比较目标与现状，产出差距、备选方案、分阶段路线图、治理责任和验收指标。
- 对 SOA、微服务、PBC、云原生、AI 等只做场景化选型与权衡，不预设企业必须采用某套技术栈。

它的优势在于跨层可追溯和落地检查：每项建设能说明所服务的业务目标，每个关键目标能找到支撑能力、数据与系统，并把未核实信息保留为待确认项。依据用户资料提炼的方法与 [The Open Group 对 TOGAF/ArchiMate 的公开说明](https://help.opengroup.org/hc/en-us/articles/32115987894930-How-the-ArchiMate-Language-and-the-TOGAF-Standard-Complement-Each-Other)相容，但不是 TOGAF 标准全文或官方认证实施指南。云原生只是设计选项，参见 [CNCF 的定义](https://www.cncf.io/about/who-we-are/)。

企业架构与 HR 使用同一个 AIHR 入口，细节分别存于 [规划流程](references/enterprise-architecture-planning.md) 和 [设计决策](references/enterprise-architecture-decisions.md)。示例：`AIHR 梳理订单到交付的跨系统流程，输出 4A 目标蓝图、接口目录与分阶段实施路线图；未知现状请列出待调研项。`

全局安装：

```bash
git clone https://github.com/Dean202305/hr-assistant-skill.git ~/.claude/skills/aihr
```

也可以安装到当前项目：

```bash
git clone https://github.com/Dean202305/hr-assistant-skill.git .claude/skills/aihr
```

Claude Code 会从全局 `~/.claude/skills/` 或项目 `.claude/skills/` 读取技能。参考：[Claude Code 目录说明](https://code.claude.com/docs/en/claude-directory)。

### WorkBuddy

下载本仓库 ZIP，确认导入目录内保留 `aihr/SKILL.md` 和 `aihr/references/`，然后在 WorkBuddy 的“专家·技能·连接器 → 技能”中通过创建或导入入口安装。参考：[WorkBuddy Skill 文档](https://open.workbuddy.cn/en/docs/skill)。

### DeepSeek Harness

项目级安装：

```bash
git clone https://github.com/Dean202305/hr-assistant-skill.git .dsh/skills/aihr
```

也可以安装到项目 `.agents/skills/`、用户 DSH Skills 目录，或配置的自定义 Skill 目录。DeepSeek Harness 不递归发现任意层级的 `SKILL.md`，因此 `aihr` 应直接位于某个 Skill 根目录下。参考：[DeepSeek Harness Skills](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md)。

### OpenClaw

工作区安装：

```bash
git clone https://github.com/Dean202305/hr-assistant-skill.git skills/aihr
```

也可以放入工作区 `.agents/skills/` 或 OpenClaw 配置的其他技能目录。参考：[OpenClaw Skills](https://docs.openclaw.ai/skills)。

### 其他兼容软件

将仓库克隆或复制到软件配置的 Skill 根目录，保证目录形态如下：

```text
<skill-root>/
└── aihr/
    ├── SKILL.md
    └── references/
```

如果软件不支持自动发现，可在系统提示词或项目指令中要求智能体：遇到“AIHR”时先读取 `aihr/SKILL.md`，再按关键词读取相关 `references/` 文件。

## 使用示例

安装后，直接输入“AIHR + 需求”；在需要显式技能调用的平台，可使用 `$aihr` 或该平台的对应命令。例如：

```text
AIHR 为我创建员工花名册，身份证信息需要自动校验。
```

```text
AIHR 按北京和上海两地政策制作本年度社保公积金核算表。
```

```text
AIHR 分析这个目录里的全部简历，按中等标准筛选算法实习生。
```

```text
AIHR 草拟国庆节放假通知，先给标准版，再提供一版和蔼风格。
```

```text
AIHR 根据通用版题库制作 360 度环评表，先保留原始选项并统计各题分布。
```

```text
AIHR 为客服主管建立岗位胜任力模型，先做能力词典和行为分级草案，不预设权重。
```

```text
AIHR 建立人才盘点九宫格，先定义绩效和目标岗位潜力的分档，再生成可校准的人才地图。
```

```text
AIHR 根据已批准的岗位和员工台账建立入职、试用转正、续签和离职跟进清单，列出责任人与未完成事项。
```

```text
AIHR 核查这次拟调岗事项的事实、制度、程序和证据缺口，先给风险清单，不发送通知。
```

```text
AIHR 按今年已批准编制和工资预算做下季度人力成本情景分析，缺失参数保留待确认。
```

## 文件结构

```text
aihr/
├── SKILL.md
├── agents/
│   └── openai.yaml        # 可选的平台展示元数据，不影响其他平台读取
└── references/
    ├── automations.md
    ├── 360-feedback.md
    ├── china-id-rules.md
    ├── competency-model.md
    ├── enterprise-architecture-decisions.md
    ├── enterprise-architecture-planning.md
    ├── employee-lifecycle.md
    ├── employment-risk-check.md
    ├── internal-document-drafting.md
    ├── payroll-template.md
    ├── resume-screening.md
    ├── talent-review.md
    ├── workforce-planning.md
    └── workbook-specs.md
```

`SKILL.md` 负责统一触发、关键词路由和通用边界；`references/` 按任务类型提供详细规则，使每次调用只读取相关知识库。`agents/openai.yaml` 只是可选的界面元数据，其他平台可以忽略，不影响核心能力。
